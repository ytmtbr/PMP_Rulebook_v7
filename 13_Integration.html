13 Integration

Rule 1　Project Integration Management

Business Need ↓ Project Charter ↓ Project Management Plan ↓ Direct & Manage Project Work ↓ Manage Project Knowledge ↓ Monitor & Control Project Work ↓ Integrated Change Control ↓ Close Project / Phase

Integration Managementは、 Scope・Schedule・Costなどを個別に管理するのではなく、 Project全体を統合して意思決定する。

各Knowledge Areaを独立して最適化。 一つの制約だけ見てDecision。
Integration = Whole Project

Rule 2　Project Charter

Business Need / Business Case ↓ Sponsor ↓ Project Charter ↓ Formal Authorization ↓ PM Authority

Project CharterはProjectを正式にAuthorizeし、 Project Managerへ組織Resourcesを使用するAuthorityを与える。

PMが自分でProjectをAuthorize。 Project Management Plan完成後にCharter作成。 Charter = 詳細Project Plan。
Charter Authorizes Project + PM

Rule 3　Project Charterに含まれるもの

High-level Purpose + High-level Scope + High-level Requirements + High-level Risks + Summary Milestones + Summary Budget + Success Criteria + Key Stakeholders + PM Authority
詳細WBS。 詳細Schedule。 詳細Risk Register。 詳細Cost Baseline。
Charter = High Level

Rule 4　Project Management Plan

Subsidiary Management Plans + Baselines + Management Approach ↓ Integrated Project Management Plan

Project Management Planは、 ProjectをどのようにExecute・Monitor・Control・Closeするかを統合する。

Project Management Plan = Scheduleだけ。 Project Management Plan = Document一覧。
PMP Plan = Integrated HOW

Rule 5　Project Management Planの構造

Project Management Plan ↓ Subsidiary Plans + Baselines
Subsidiary Plans Baselines
Scope Management Plan Scope Baseline
Schedule Management Plan Schedule Baseline
Cost Management Plan Cost Baseline
Quality Management Plan Performance Measurement Baseline
Risk Management Plan ―
Communications Management Plan ―
Procurement Management Plan ―
Stakeholder Engagement Plan ―
Risk RegisterをRisk Management Planと思う。 WBSだけをScope Baselineと思う。
Plan = How to Manage Baseline = Approved Reference

Rule 6　Project Management Plan vs Project Documents

Project Management Plan Project Documents
Management Approach Current Project Information
How work is managed Registers / Logs / Estimates
Baselinesを含む Execution中に継続更新
Examples of Documents ↓ Risk Register Issue Log Stakeholder Register Lessons Learned Register Requirements Documentation RTM Change Log
Risk Register = Risk Management Plan。 Stakeholder Register = Stakeholder Engagement Plan。
Plan = HOW Documents = Project Information

Rule 7　Direct and Manage Project Work

Approved Project Management Plan ↓ Execute Planned Work ↓ Implement Approved Changes ↓ Produce Deliverables ↓ Generate Work Performance Data ↓ Raise Change Requests if Needed
未承認Changeを実装。 MonitoringだけしてExecutionしない。
Execute Approved Work

Rule 8　Monitor and Control Project Work

Actual Performance ↓ Compare with Plan / Baselines ↓ Analyze Variance / Trends ↓ Forecast ↓ Determine Action ↓ Change Request if Needed

Monitor & Controlは単なるStatus確認ではない。 Variance・Trend・Forecastを分析し、 Project全体への対応を決める。

問題が発生してからだけ確認。 Actual Dataを集めて終了。 Varianceが出たらBaselineを書き換える。
Compare ↓ Analyze ↓ Act

Rule 9　Integrated Change Control

Change Request ↓ Evaluate Whole-project Impact ↓ Review / Approve / Reject ↓ Update Relevant Plans / Baselines ↓ Communicate ↓ Implement ↓ Verify

Integratedの意味は、 ScopeだけでなくSchedule・Cost・Quality・Risk・Resources・ Stakeholders・Business Valueへの影響を横断的に見ること。

Scope Change → Scopeだけ評価。 Sponsor要求 → Impact Analysisなしで実施。
Change One Thing ↓ Check Everything

Rule 10　Work Performance Data / Information / Reports

Type Meaning Example
Work Performance Data Raw observations Actual cost / completed work / defect count
Work Performance Information Analyzed / contextualized data CPI / SPI / variance / trend
Work Performance Reports Decision-useful presentation Status report / dashboard / forecast report
Data ↓ Analyze ↓ Information ↓ Organize / Present ↓ Reports
Raw Actual Cost = Work Performance Information。 CPI = Raw Data。
Data ↓ Information ↓ Reports

Rule 11　Issue Management

Issue Occurs ↓ Understand / Analyze ↓ Record in Issue Log ↓ Assign Owner ↓ Take Action ↓ Monitor Resolution ↓ Change Request if Required

Issueは既に発生した問題。 Issue Logへ記録すること自体が解決ではなく、 OwnerとActionを決めてResolutionまで管理する。

Issue発生 → Risk Registerだけ更新。 Issue Log更新 → 対応完了。
Issue = Happened ↓ Act

Rule 12　Manage Project Knowledge

Existing Knowledge ↓ Apply to Project ↓ Generate New Knowledge ↓ Capture ↓ Share ↓ Reuse

Knowledge Managementは、 過去のLessons Learnedを使うだけでなく、 Project中に得たTacit / Explicit Knowledgeを共有・再利用する。

Knowledge Management = Document保存だけ。 Project CloseまでKnowledgeを記録しない。
Use Knowledge ↓ Create Knowledge ↓ Share Knowledge

Rule 13　Lessons LearnedはContinuous

Experience / Event ↓ Capture Lesson ↓ Lessons Learned Register ↓ Apply During Current Project ↓ Share ↓ Archive at Close

Lessons LearnedはProject終了時だけ作るものではない。 Project中にも継続してCaptureし、 同じProject内でも再利用する。

Closeoutで初めてLessons Learned Meeting。 失敗だけを記録。 責任者を特定するために使う。
Learn Throughout the Project

Rule 14　Project Knowledge Transfer

Critical Knowledge Identified ↓ Transfer ↓ Document ↓ Confirm Understanding ↓ Make Knowledge Available

特にResource交代やTransitionでは、 Tacit Knowledgeが失われる前にTransferする。

Documentation Repositoryだけ用意。 Member離任後にKnowledge Transfer。
Transfer Before Knowledge Leaves

Rule 15　Project / Phase Closing

Confirm Work Complete ↓ Obtain Formal Acceptance ↓ Complete Contract / Administrative Closure ↓ Transition Deliverables ↓ Finalize Records ↓ Capture Final Lessons Learned ↓ Archive ↓ Release Resources
Deliverable完成 → 即Project終了。 Team解散 → 後からAcceptance。 Lessons Learnedだけ実施して終了。
Accept ↓ Close ↓ Archive ↓ Release

Rule 16　Acceptance vs Closing

Deliverable Verification ↓ Customer / Sponsor Acceptance ↓ Project / Phase Closure

成果物がTechnicalに完成したことと、 Customerが正式にAcceptanceしたこと、 Projectが正式にCloseされたことは別。

Testing Passed = Project Closed。 Product Delivered = Administrative Closure完了。
Complete ≠ Accepted ≠ Closed

Rule 17　Integration Decision Thinking

Major Decision ↓ Check Impact on Scope + Schedule + Cost + Quality + Resources + Risk + Procurement + Stakeholders + Business Value ↓ Choose Best Overall Project Outcome
Costだけ最小化。 Scheduleだけ守る。 Qualityだけ最大化。 一つのStakeholder要求だけ最適化。
Optimize the Whole Project

Rule 18　Integration問題の「まず何を見る？」

Need Overall Project Direction? ↓ Project Management Plan Need Authorization / High-level Purpose? ↓ Project Charter Need Current Specific Information? ↓ Project Documents Need Actual vs Plan? ↓ Work Performance Information Need Plan / Baseline Change? ↓ Integrated Change Control
何でもProject Management Plan。 何でもRisk Register。 何でもSponsorへ確認。
Choose the Artifact that Matches the Question

Rule 19　Integration Summary

Business Need ↓ Charter ↓ Integrated Project Management Plan ↓ Execute ↓ Manage Knowledge ↓ Monitor & Control ↓ Integrated Change Control ↓ Formal Close

試験で迷ったら

  • Integration = Project全体を見る
  • Charter = ProjectとPMをAuthorizeするHigh-level文書
  • Project Management Plan = Integrated HOW
  • Project Documents = Current Project Information
  • 実行するのはApproved Work / Approved Changes
  • MonitorではActual vs Baselineを比較して分析する
  • Changeでは一つのKnowledge Areaだけ見ない
  • Data → Information → Reportsを区別する
  • Issue Logへ記録するだけで終わらない
  • Lessons LearnedはProject中も継続する
  • Knowledge TransferはKnowledgeが失われる前に行う
  • Complete ≠ Accepted ≠ Closed
  • 個別最適ではなくProject全体のOutcomeを最適化する
Whole Project ↓ Integrated Plan ↓ Integrated Decision ↓ Integrated Change
