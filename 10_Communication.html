10 Communication

Rule 1　Communication Management Flow

Identify Stakeholders ↓ Analyze Stakeholders ↓ Determine Information Needs ↓ Plan Communications ↓ Manage Communications ↓ Monitor Effectiveness
Stakeholderを理解する前にCommunication Planを作る。 全員に同じCommunicationを行う。
Stakeholders First Communication Second

Rule 2　Communications Management Plan

Who Needs Information? ↓ What Information? ↓ Why? ↓ When / Frequency? ↓ How / Channel? ↓ Who Sends It?

Communications Management Planは、 Stakeholderへ必要な情報を 「誰に・何を・いつ・どう伝えるか」を定める。

StakeholderのRequirementそのものを書く。 Quality Requirementを定義する。 StakeholderのEngagement Levelを決める。
Communication Plan = Information Delivery

Rule 3　Communication vs Engagement

Communication Stakeholder Engagement
情報をどう共有するか Stakeholderをどう関与させるか
Who / What / When / How Support / Resistance / Participation
Communications Management Plan Stakeholder Engagement Plan
Stakeholder Resistance → Communication Planだけ更新。 Information Delivery問題 → Engagement Matrixだけ見る。
Communication = Information Engagement = Involvement

Rule 4　Communication Problem

Communication Failure ↓ Understand Root Cause ↓ Clarify Message ↓ Adjust Method / Channel ↓ Confirm Understanding ↓ Monitor
Meetingを増やすだけ。 Sponsorへ即Escalate。 同じCommunicationを繰り返す。
Understand Cause Before Changing Method

Rule 5　Interactive / Push / Pull

Method Example Best For
Interactive Meeting / Call / Workshop 双方向・複雑な議論
Push Email / Report / Memo 特定相手へ情報送付
Pull Repository / Portal / Wiki 大量情報を必要時に取得
重要情報はすべてMeeting。 大量Documentを全員へEmail。
Discuss → Interactive Send → Push Access → Pull

Rule 6　Communication Methodは目的に合わせる

Purpose ↓ Audience ↓ Complexity / Urgency / Sensitivity ↓ Select Appropriate Method
Situation Typical Method
複雑・Conflictを含む議論 Interactive Discussion
定期Status共有 Dashboard / Report
大量のReference情報 Repository
Agile Work Visibility Task Board / Information Radiator
正式通知 Governance / Contractで指定された方法
全部Meeting。 Formal Communication = 必ずEmail。
Fit Method to Purpose

Rule 7　Feedback Loop

Sender ↓ Message ↓ Receiver ↓ Feedback ↓ Confirm Understanding ↓ Adjust if Needed

Communicationは「送った」だけでは成立しない。 相手が意図どおり理解したことまで確認する。

Email送信 = Communication完了。
Sent ≠ Understood

Rule 8　Active Listening

Listen ↓ Ask / Clarify ↓ Paraphrase ↓ Confirm Understanding ↓ Respond
話を途中で遮ってSolutionを提示。 自分の理解を確認せず回答。
Listen Clarify Confirm

Rule 9　Virtual / Global Team

Distributed Team ↓ Consider Time Zone + Language + Culture + Technology ↓ Tailor Communication

Global TeamではCommunication Methodを Teamの環境に合わせてTailorする。

全拠点へ同じ時間帯を強制。 Face-to-face前提で考える。
Global Team = Tailor Communication

Rule 10　Language Barrier / Information Radiator

Language / Accent Barrier ↓ Reduce Dependence on Verbal Communication ↓ Electronic Task Board ↓ Visual Status ↓ Shared Understanding
口頭報告をさらに増やす。 最初から高価なTranslation Service。
When Words Fail Visualize

Rule 11　Communication Channels

Number of Channels = n(n−1) ÷ 2

n = Communicationに参加する人数。

People Channels
5 10
10 45
20 190
人数が2倍 = Communication Complexityも2倍。
Channels = n(n−1)/2

Rule 12　Status Reporting

Collect Accurate Data ↓ Analyze Performance ↓ Report Objective Status ↓ Highlight Risks / Issues / Trends ↓ Communicate Actions

Status Reportは「良く見せる」ものではない。 現在の事実だけでなく、 悪化しているTrendも透明に報告する。

Milestoneが予定どおりだからGreen。 悪いTrendを隠す。 Sponsorを安心させるためStatusを調整。
Accurate Transparent Timely

Rule 13　Communication Escalation

Understand Problem ↓ Communicate Directly ↓ Clarify ↓ Attempt Resolution ↓ Escalate if Unresolved / Outside Authority
重要Stakeholderだから即SponsorへEscalate。 Communication Gapだけで上位Managementへ報告。
Resolve First Escalate When Necessary

Rule 14　Communication Planを更新する時

Communication Need Changes ↓ Assess Impact ↓ Update Communication Strategy / Plan ↓ Communicate Using New Approach ↓ Monitor Effectiveness

組織変更、Stakeholder変更、 Communication Failureなどで情報ニーズが変化したら、 Communication方法もTailorする。

Project開始時に作ったPlanを最後まで固定。 問題が起きるたびMeetingを追加。
Communication Plan is Tailored as Needs Change

Rule 15　Communication Summary

Stakeholders ↓ Information Needs ↓ Plan ↓ Communicate ↓ Feedback ↓ Confirm Understanding ↓ Monitor / Adapt

試験で迷ったら

  • Stakeholderを理解してからCommunicationを設計する
  • Communication Plan = 情報をどう届けるか
  • Engagement = Stakeholderをどう関与させるか
  • Communication Problemではまず原因を理解する
  • Interactive / Push / Pullを目的で使い分ける
  • 送信しただけではCommunication完了ではない
  • Feedbackで理解を確認する
  • Global TeamではLanguage・Culture・Time Zoneを考慮する
  • Language BarrierにはVisual Toolが有効
  • Statusは正確・透明に報告する
  • Escalationは最初の手段ではない
Understand ↓ Clarify ↓ Communicate ↓ Confirm
