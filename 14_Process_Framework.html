14 Process Framework

Rule 1　5 Process Groups

Initiating ↓ Planning ↓ Executing ↕︎ Monitoring & Controlling ↓ Closing

5 Process Groupsは単純なProject Phaseではない。 特にExecutingとMonitoring & Controllingは Project中に並行・反復して行われる。

Planningが完全終了してからMonitoring開始。 Executing完了後にMonitoring。 Process Group = Project Phase。
I P E ↔ M&C C

Rule 2　Process GroupとProject Phaseを混同しない

Process Groups = How Project Management Work Is Performed Project Phases = How Project / Product Work Is Organized

Design PhaseやConstruction Phaseなどの各Phaseの中でも、 Planning・Executing・Monitoringなどが行われ得る。

Initiating = 必ずProject最初のPhase。 Closing = Project全体の最後だけ。
Process Group ≠ Project Phase

Rule 3　問題を読むときの4ステップ

① What is happening? ↓ ② Predictive / Agile / Hybrid? ↓ ③ Risk / Issue / Change / Conflict / Requirement? ↓ ④ What is the FIRST / NEXT appropriate action?
Keywordだけ見てToolを選ぶ。 選択肢から先に読む。 状況を分類せず暗記ルールだけ適用。
Context Before Answer

Rule 4　FIRST / NEXT問題

FIRST = What must happen before the other actions? NEXT = Given what has already happened, what is the next logical action?

正しいActionが複数あっても、 順番が違えば不正解になる。 問題文で「既に何が済んでいるか」を確認する。

最終的に必要なActionをFIRSTで選ぶ。 既に実施済みのAnalysisをもう一度選ぶ。
Correct Action + Correct Sequence

Rule 5　基本Decision Flow

Understand Situation ↓ Gather / Review Relevant Information ↓ Analyze ↓ Collaborate if Needed ↓ Decide ↓ Act through Appropriate Process ↓ Monitor Result
UnderstandせずAction。 AnalyzeせずDecision。 実施してMonitorしない。
Understand ↓ Analyze ↓ Act ↓ Verify

Rule 6　「まずAnalyze」は強いが絶対ではない

Unknown Cause / Impact ↓ Analyze First Already Analyzed ↓ Do Not Analyze Again Immediate Safety / Compliance Threat ↓ Protect / Correct Immediately Clear Existing Problem within Authority ↓ Take Appropriate Action

「何でもImpact Analysis」は危険。 問題文ですでに原因・Impact・対応方針が明確なら、 次のProcessへ進む。

すべての問題 → Analyze。 明確なDefect → さらに原因分析だけして修正しない。
Analyze when information is missing

Rule 7　Risk / Issue / Changeを最初に分類

Situation Think
将来起こるかもしれない Risk
既に起きている Issue
Approved Plan / Baselineを変える Change
Risk → Analyze / Response / Monitor Issue → Resolve / Track Change → Impact / Approval / Update / Implement
既発生EventをRisk Registerへ入れて終了。 Potential RiskをIssueとして即修正。 Issue発生 = 自動的にBaseline変更。
Future → Risk Happened → Issue Plan Changes → Change

Rule 8　Plan vs Execute vs Monitor

Question Intent Think
どう管理するか決める Plan
承認済みWorkを行う Execute
Actual vs Plannedを見る Monitor / Control
Baselineを変更する Change Control
完了・受入・Archive Close
Planを作る問題で実装。 Monitoring問題で新しいPlanをゼロから作る。
Plan ↓ Do ↓ Check ↓ Adjust

Rule 9　Predictiveの基本思考

Requirements ↓ Scope ↓ WBS ↓ Plan / Baselines ↓ Execute ↓ Monitor & Control ↓ Formal Change ↓ Close
Approved Baselineを非公式に変更。 Customer要求を即実装。
Predictive = Plan + Baseline + Control

Rule 10　Agileの基本思考

Value ↓ Prioritized Backlog ↓ Small Increment ↓ Feedback ↓ Inspect & Adapt ↓ Repeat

AgileではCommand & Controlより、 Team Collaboration・Feedback・Adaptation・Value Deliveryを優先する。

Detailed Long-term Planを固定。 PMがTaskを毎日割り当てる。 変化を防ぐ。
Value ↓ Feedback ↓ Adapt

Rule 11　Hybridの基本思考

Predictive Governance + Adaptive Delivery ↓ Hybrid

Hybridでは、 Delivery方法は柔軟にAdaptしながら、 BaselineやGovernanceが必要な領域ではFormal Controlを維持する。

Hybrid = 全部Predictive。 Hybrid = 全部Agile。
Adapt Delivery Preserve Governance

Rule 12　PMIのPeople問題の基本順序

Understand ↓ Discuss / Coach ↓ Collaborate ↓ Facilitate ↓ Resolve ↓ Escalate if Necessary
Command。 Blame。 Punish。 Replace。 Escalate First。
Coach First Escalate Last

Rule 13　Escalationを選ぶ条件

Can PM / Team Resolve? ↓ YES → Resolve at Current Level NO ↓ Outside Authority or Unresolved after Appropriate Action ↓ Escalate

Escalationは悪いActionではないが、 PMが自分のAuthorityで解決できる問題に最初から使わない。

Senior Stakeholderが関係 → Sponsorへ即Escalate。 問題が重大 → 自動的にEscalate。
Escalate when necessary not automatically

Rule 14　Meeting / Workshopを過大評価しない

Need Information / Alignment / Collaboration? ↓ Meeting may be appropriate Known Defect? ↓ Correct it Need Quantitative Assessment? ↓ Analyze Need Formal Change? ↓ Change Control
対立がある → Meeting。 問題がある → Workshop。 Stakeholderがいる → Meeting。
Choose Action that solves the actual problem

Rule 15　DocumentはActionの代わりではない

Document + Take Appropriate Action + Monitor

Risk Register、Issue Log、Change Log等への記録は重要だが、 記録しただけでは問題を解決していない。

Risk Register更新 → 完了。 Issue Log更新 → 完了。 Status Report作成 → 問題解決。
Document ≠ Resolve

Rule 16　Review Existing Information Before Creating New

Problem / Decision ↓ Review Relevant Plan Register Baseline Contract RTM WBS Dictionary Lessons Learned ↓ Then Decide / Update

既存の正式情報に答えがある場合、 新しいProcessやDocumentを作る前にそれを確認する。

Ownership不明 → PMが勝手に決定。 Requirement Conflict → 新しいMeetingだけ実施。
Check Existing Artifacts First

Rule 17　PMIが好むAction

Understand Analyze Collaborate Coach Facilitate Communicate Document Follow Governance Monitor Improve
Ignore Assume Blame Hide Bypass Act Alone Skip Process
Structured Collaborative Transparent

Rule 18　極端な選択肢に注意

Usually Suspicious ↓ Immediately Replace Immediately Escalate Stop All Work Ignore Always Never Freeze Everything

極端なActionが必ず不正解という意味ではない。 Safety・Legal・Critical Quality等では 強いActionが必要な場合もあるため、 Contextで判断する。

「Immediately」がある → 自動的に不正解。 「Stop」がある → 自動的に不正解。
Extreme Action needs Extreme Context

Rule 19　情報不足ならAssumeしない

Missing Information ↓ Do Not Invent Facts ↓ Clarify / Review / Analyze ↓ Then Decide

問題文に書かれていない 「冗長Processがある」 「Vendorが悪い」 「Resourceを追加できる」 などを勝手に仮定しない。

もっともらしい前提を自分で追加して選択肢を正当化。
Use Only Given Facts

Rule 20　最も直接的に問題を解くActionを選ぶ

Question asks X ↓ Which Option Directly Addresses X while following PMI principles? ↓ Choose It

正しいProject Management Practiceでも、 問題文が聞いている課題を直接解決しなければ Best Answerではない。

一般的に良いActionだから選ぶ。 関連するTool名が出ているから選ぶ。
Relevant Direct Appropriate

Rule 21　PMP Decision Ladder

1. What actually happened? ↓ 2. Future Risk or Existing Issue? ↓ 3. Predictive / Agile / Hybrid? ↓ 4. Is information sufficient? ↓ 5. Is analysis required? ↓ 6. Can PM / Team resolve it? ↓ 7. Is formal governance required? ↓ 8. Act ↓ 9. Verify / Monitor
Context ↓ Classify ↓ Analyze ↓ Act ↓ Verify

Rule 22　Process Framework Summary

Understand Context ↓ Classify the Problem ↓ Identify Delivery Approach ↓ Review Existing Information ↓ Analyze if Needed ↓ Collaborate / Decide ↓ Use Appropriate Process ↓ Act ↓ Monitor / Verify

試験で迷ったら

  • FIRST / NEXTでは順番を見る
  • 問題文ですでに何が実施済みか確認する
  • Future = Risk、Happened = Issue
  • 何でもAnalyzeではない
  • 何でもMeetingではない
  • Document更新だけで問題解決と考えない
  • PredictiveではBaselineとFormal Changeを守る
  • AgileではValue・Feedback・Adaptationを見る
  • HybridではAdaptive Delivery + Governance
  • People問題はCoach / Facilitateを優先する
  • Escalationは必要な場合のみ
  • 問題文にない事実を仮定しない
  • 極端なActionには極端なContextが必要
  • 最も直接的に問題を解決する選択肢を選ぶ
Understand ↓ Classify ↓ Analyze ↓ Act ↓ Verify
