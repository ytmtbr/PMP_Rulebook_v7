PMP Personal Rulebook v7 - 04 Quality
トップ 01 Stakeholder 02 Governance 03 Risk 04 Quality Final Checklist

04 Quality Management

品質・監査・DoD・Cost of Quality・Compliance・受入の判断ルール。

Rule 1　QualityはCost・Scheduleより先に守る

Critical defect / Regulatory violation / Contract quality failure → Stop release or reject delivery → Correct the defect → Verify compliance and quality → Release only after acceptance criteria are met
出荷後に保証で直す、納期を守るために妥協する、簡単な欠陥だけ直す、は不正解。
Critical defect = Fix before release.

Rule 2　品質基準の変更はChange Controlへ

New or higher quality standard requested → Impact analysis → Evaluate scope / cost / schedule / risk → Formal change request → Approval → Update quality plan and baselines
顧客満足のため即承認しない。非公式な設計変更をしない。
Quality change = Analyze, then govern.

Rule 3　Quality AuditとQuality Control

Quality Audit = プロセスが正しく実施されているか Quality Control / Testing = 成果物が基準を満たすか
製品試験をAuditと混同しない。
Audit checks process. Testing checks product.

Rule 4　AuditでGapが見つかったら是正する

Audit finding confirmed → Implement corrective action → Verify effectiveness → Resume or continue under control
Meetingだけ、Closeoutまで延期、軽微として無視、は不正解。
Known quality gap = Corrective action.

Rule 5　承認済み変更は実装確認まで行う

Approved change → Update baseline / plan → Implement → Quality audit or verification → Confirm effectiveness
Change LogやBaseline更新は実装確認ではない。
Approved does not mean implemented.

Rule 6　Definition of Done

Completed work → Check acceptance criteria → Check testing / review / quality conditions → Confirm Definition of Done → Mark Done
コード完了、レビュー依頼済み、Done列増加だけではDoneではない。
Done = DoD satisfied.

Rule 7　Cost of Quality

Additional testing / prevention → Evaluate prevention and appraisal costs → Compare with internal and external failure costs → Assess long-term value → Request change if warranted
品質部門またはOperationsの片方を無条件で採用しない。
COQ = Prevention now vs failure later.

Rule 8　Inspection削減を安易に選ばない

Budget pressure + request to reduce inspections → Preserve agreed quality requirements → Explain trade-offs → Change only through analysis and approval
問題文に冗長性が書かれていないのに「無駄がある」と仮定しない。
Do not invent redundancy.

Rule 9　Quality Requirementsは文書化してから合意

Different stakeholder definitions of quality → Capture requirements → Document source and rationale → Prioritize → Agree → Baseline
Risk RegisterやCommunication Planで代用しない。
Different quality views = Document requirements.

Rule 10　客観的な証拠を優先

Transition readiness / acceptance / compliance → Use certification, testing, inspection, or measurable evidence → Confirm standards are consistently met
Stakeholderの主観的合意や内部記録だけで品質を証明しない。
Quality needs objective evidence.

Rule 11　Contract Quality

Vendor delivery fails contractual quality criteria → Reject or require correction → Enforce contract terms → Accept only after compliance
納期のため受入、Warranty延長、非公式な譲歩は避ける。
Contract quality failure = Do not accept.

Rule 12　Quality Issueの優先順位

Evaluate each issue separately → Assess severity and impact → Prioritize safety / compliance / customer-impact issues → Act first on the highest-impact issue
Revenueや過去記録だけで優先順位を決めない。
Prioritize by impact.

Rule 13　Leading Indicatorsを無視しない

Milestones green but defect density / rework rising → Report honest status → Use yellow or at-risk status → Explain mitigation actions
Milestoneが予定どおりでも品質Trendを無視しない。
Trend can override a superficial green.

Rule 14　品質問題は目的に直結する手段を選ぶ

Known defect or confirmed gap → Correct / test / verify Requested quality change → Analyze first Unknown cause → Investigate / root-cause analysis
何でもWorkshopやMeetingを選ばない。
Choose the action that directly resolves the problem.

Rule 15　Quality Summary

Requirements → Quality plan → Prevention and assurance → Testing and control → Correct defects → Verify acceptance → Release
最後にまとめて検査、コスト圧力で基準を下げる、承認済みだから検証不要、は不正解。
Plan quality, build quality, verify quality.
